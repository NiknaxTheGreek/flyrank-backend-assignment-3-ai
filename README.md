# FlyRank Backend Assignment 3

A standalone task API that preserves the Assignment 1/2 CRUD surface while moving the runtime to **FastAPI + PostgreSQL**. Docker Compose starts a FastAPI `api` service and a PostgreSQL `db` service, waits for database health, creates the `tasks` table, and inserts exactly three starter tasks only when the table is empty.

## API contract

| Method | Path | Success | Notes |
| --- | --- | --- | --- |
| `GET` | `/health` | `200` | Liveness endpoint |
| `GET` | `/tasks` | `200` | Lists tasks |
| `POST` | `/tasks` | `201` | Requires a non-blank `title` |
| `GET` | `/tasks/{task_id}` | `200`, `404` | Reads one task |
| `PUT` | `/tasks/{task_id}` | `200`, `400`, `404` | Partial update; omitted fields are preserved |
| `DELETE` | `/tasks/{task_id}` | `204`, `404` | Returns an empty response body |

Bad payloads and malformed numeric IDs return `400`. Missing numeric IDs return `404`. All production SQL values are bound as query parameters.

## Run with Docker

```bash
cp .env.example .env
docker compose up --build
```

Then open `http://localhost:8000/docs`, or try:

```bash
curl http://localhost:8000/tasks
curl -X POST http://localhost:8000/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Finish the FlyRank assignment"}'
```

Stop the stack without erasing task data:

```bash
docker compose down
```

Use `docker compose down -v` only when you deliberately want to remove the named PostgreSQL volume.

## Local regression suite

Install the Python dependencies and run:

```bash
python -m pytest backend/tests -q
```

The HTTP regression suite uses an isolated in-memory repository so it is deterministic and does not require a local database. Docker/PostgreSQL proof is intentionally separate:

```bash
./scripts/verify_docker_runtime.sh
```

That script starts a fresh Compose project, exercises live CRUD, inspects PostgreSQL directly with `psql`, restarts the stack without `-v`, and confirms persistence. It requires an actual Docker-capable runner.
